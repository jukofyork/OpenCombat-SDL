# VEHICLE COMBAT IMPLEMENTATION PLANS

## ANALYSIS SUMMARY

THE ORIGINAL AUTHOR'S NOTES (IN ORIGINAL/DOCS/) DO NOT MENTION VEHICLE COMBAT AT ALL.
THE TODO.TXT AND BUGS.TXT FILES FROM 2005-2007 ARE SILENT ON THIS FEATURE.
THIS SUGGESTS VEHICLE COMBAT WAS NEVER PART OF THE ORIGINAL DESIGN SCOPE.

THE `#IF 0` BLOCK IN VEHICLE.CPP CONTAINS A COMMENT EXPLICITLY STATING:
"THIS #IF 0 BLOCK WAS ALREADY DISABLED IN THE ORIGINAL DIRECTX/WINDOWS CODE FROM 2005!
THE G_WORLD->CALCULATESHOT() FUNCTION NEVER EXISTED IN THE WORLD CLASS."

THIS CONFIRMS THAT VEHICLE COMBAT WAS NEVER IMPLEMENTED IN THE ORIGINAL GAME.

## CURRENT STATE OF COMBAT

### WHAT WORKS:
- SOLDIER -> SOLDIER: CALCULATESHOT() METHOD EXISTS AND WORKS (10 HP PER ROUND)
- VEHICLE -> CAN FIRE WEAPONS AND SHOW EFFECTS (MUZZLE FLASH, EXPLOSION)
- VEHICLE -> CANNOT DEAL DAMAGE (NO CALCULATESHOT() METHOD)
- SQUAD -> CAN CONTAIN BOTH SOLDIERS AND VEHICLES

### WHAT IS BROKEN:
- VEHICLE -> SOLDIER: FIRES BUT DOES ZERO DAMAGE
- SOLDIER -> VEHICLE: CANNOT TARGET VEHICLES (NO CASE TARGET::VEHICLE IN SOLDIER::SHOOT)
- VEHICLE -> VEHICLE: NOT IMPLEMENTED
- VEHICLE::ISDESTROYED() ALWAYS RETURNS FALSE
- VEHICLE::FINDTARGET() ONLY RETURNS SOLDIER*, NOT VEHICLE*

## IMPLEMENTATION OPTIONS

### OPTION 1: MINIMAL VIABLE IMPLEMENTATION (FOLLOW EXISTING PATTERNS)

#### CHANGES NEEDED:
1. ADD `VEHICLE::CALCULATESHOT(SOLDIER* SHOOTER, WEAPON* WEAPON)` METHOD
   - SIMILAR TO SOLDIER::CALCULATESHOT()
   - SIMPLE HEALTH-BASED DAMAGE: `_HEALTH -= WEAPON->GETROUNDSPERBURST() * 10`
   - WHEN HEALTH <= 0, PLAY WRECK ANIMATION AND MARK AS DESTROYED

2. ADD `CASE TARGET::VEHICLE:` TO VEHICLE::SHOOT()
   - HANDLE VEHICLE-ON-VEHICLE COMBAT
   - REUSE SAME CALCULATESHOT LOGIC

3. ADD `CASE TARGET::VEHICLE:` TO SOLDIER::SHOOT()
   - ONLY ALLOW BAZOOKA TO TARGET VEHICLES
   - CHECK WEAPON NAME OR ADD NEW XML ATTRIBUTE

4. IMPLEMENT VEHICLE::ISDESTROYED() AND VEHICLE::ISABANDONED()
   - RETURN BASED ON _HEALTH AND CREW STATUS

#### PROS:
- FOLLOWS EXISTING CODE PATTERNS (SOLDIER::CALCULATESHOT)
- MINIMAL CHANGES TO XML FILES
- WORKS WITH EXISTING WEAPON STATS
- QUICK TO IMPLEMENT (1-2 HOURS)
- MAINTAINS CONSISTENCY WITH CURRENT COMBAT SYSTEM

#### CONS:
- NO ARMOR/ANTI-TANK DISTINCTION (ALL WEAPONS DAMAGE VEHICLES EQUALLY)
- UNREALISTIC (RIFLE ROUNDS SHOULD NOT DAMAGE TANKS)
- NO HIT LOCATION (FRONT/SIDE/REAR ARMOR DIFFERENCES)
- REQUIRES HARDCODING "BAZOOKA" CHECK OR WEAPON NAME PARSING

   ```XML

       <NAME>PANZER IVG</NAME>

           <FRONT>80</FRONT>
           <SIDE>30</SIDE>
           <REAR>20</REAR>
           <TOP>10</TOP>
       </ARMOR>
       <HEALTH>500</HEALTH>
   </VEHICLE>
   ```

3. IMPLEMENT HIT LOCATION CALCULATION:
   - DETERMINEHITLOCATION(VEHICLE* TARGET, OBJECT* SHOOTER)
   - CALCULATE WHICH SIDE IS FACING THE SHOOTER

4. IMPLEMENT PENETRATION FORMULA:
   ```CPP
   BOOL VEHICLE::CALCULATESHOT(OBJECT* SHOOTER, WEAPON* WEAPON, HITLOCATION LOCATION)
   {
       INT ARMOR = GETARMORAT(LOCATION);
       INT PENETRATION = WEAPON->GETPENETRATION();
       
       IF(PENETRATION > ARMOR) {
           _HEALTH -= WEAPON->GETDAMAGE();
           IF(_HEALTH <= 0) DESTROY();
           RETURN TRUE; // HIT PENETRATED
       }
       RETURN FALSE; // RICOCHET/NO DAMAGE
   }
   ```

5. ADD RICOCHET VISUAL EFFECT
   - SHOW SPARK OR "CLANG" EFFECT WHEN ROUND FAILS TO PENETRATE

#### PROS:
- MOST REALISTIC
- ALLOWS TACTICAL GAMEPLAY (FLANKING FOR SIDE/REAR SHOTS)
- DIFFERENTIATES WEAPONS (BAZOOKA VS PANZERFAUST VS CANNON)
- VEHICLES FEEL DISTINCT (TIGER VS SHERMAN ARMOR DIFFERENCES)
- REWARDING SKILL (POSITIONING MATTERS)

#### CONS:
- COMPLEX IMPLEMENTATION (6-8 HOURS)
- SIGNIFICANT XML CHANGES
- NEED NEW GRAPHICS FOR RICOCHET EFFECTS
- BALANCE TESTING REQUIRED
- MAY BE OVERKILL FOR CURRENT SCOPE

   - HANDLES ALL COMBINATIONS: SOLDIER->SOLDIER, SOLDIER->VEHICLE, VEHICLE->SOLDIER, VEHICLE->VEHICLE

2. REFACTOR SOLDIER::CALCULATESHOT() TO CALL WORLD::CALCULATESHOT()
   - MAINTAIN BACKWARDS COMPATIBILITY

3. IMPLEMENT TYPE DISPATCH IN WORLD::CALCULATESHOT():
   ```CPP
   BOOL WORLD::CALCULATESHOT(OBJECT* SHOOTER, OBJECT* TARGET, WEAPON* WEAPON)
   {
       IF(TARGET->GETTYPE() == TARGET::SOLDIER) {
           RETURN CALCULATESOLDIERDAMAGE(SHOOTER, (SOLDIER*)TARGET, WEAPON);
       } ELSE IF(TARGET->GETTYPE() == TARGET::VEHICLE) {
           RETURN CALCULATEVEHICLEDAMAGE(SHOOTER, (VEHICLE*)TARGET, WEAPON);
       }
       RETURN FALSE;
   }
   ```

#### PROS:
- WHAT THE ORIGINAL AUTHOR'S COMMENT SUGGESTED THEY WANTED
- SINGLE POINT OF CONTROL FOR ALL DAMAGE
- EASY TO ADD GLOBAL MODIFIERS (MORALE, TRAINING, ETC.)
- CLEAN SEPARATION OF CONCERNS

#### CONS:
- MAJOR REFACTORING REQUIRED
- BREAKS EXISTING SOLDIER::CALCULATESHOT() PATTERN
- MORE COMPLEX THAN NECESSARY FOR CURRENT FEATURE SET
- NO EVIDENCE THIS WAS EVER IMPLEMENTED OR TESTED

## TECHNICAL NOTES

### TARGET::TYPE ENUM ALREADY EXISTS:
```CPP
NAMESPACE TARGET {
    ENUM TYPE {
        SOLDIER, SQUAD, VEHICLE, AREA, NOTARGET, NUMTARGETTYPES
    };
}
```
THE `VEHICLE` VALUE IS NEVER USED IN ANY SWITCH STATEMENT.

### VEHICLE HEALTH:
VEHICLES INHERIT `_HEALTH` FROM OBJECT BASE CLASS.
DEFAULT VALUE IS 100 (SAME AS SOLDIERS).
VEHICLES SHOULD PROBABLY HAVE MORE HEALTH (500? 1000?).

### WEAPON STATS ALREADY LOADED:
WEAPONMANAGER ALREADY PARSES:
- ROUNDS PER BURST
- MAX EFFECTIVE RANGE
- BASE ACCURACY
ADDING DAMAGETYPE FOLLOWS EXISTING PATTERN.

### CREW SYSTEM:
VEHICLES HAVE CREW SLOTS (SOLDIER POINTERS).
CREW CAN BE KILLED SEPARATELY FROM VEHICLE.
VEHICLE SHOULD BE ABANDONED WHEN ALL CREW DEAD.
THIS IS NOT YET IMPLEMENTED.
